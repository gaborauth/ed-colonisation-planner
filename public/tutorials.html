Tutorials

Nine worked examples for turning a real planning goal into actual clicks in EDCPS — panel names and button/field labels below match the live app exactly. See also the project's README and Known issues.

Before you start (same two things, every time)

  1. Primary station — always required. In Actual facilities in the system, pick a body/building for the Primary station field. Solve for a system in the Objective panel stays disabled until this is set, no matter which tutorial below you're following.
  2. Real per-body import — only required for some tutorials (each one below says whether it needs this; the rest work fine with the flat aggregate slot counts instead). Unlocks per-body features like Economy preferences and per-slot placement:
    1. Open Import system.
    2. Journal file tab: if you've personally scanned the system's bodies in-game, upload your Journal log (on Windows: %USERPROFILE%\Saved Games\Frontier Developments\Elite Dangerous). Parses real FSS/Scan events straight out of it.
    3. Spansh tab: if you haven't scanned it yet (or want a head start), type the system name into the search box — a real autocomplete against Spansh's public system database — then hit Load. Pulls known body data from Spansh's crowdsourced dump. Heads-up shown right in the tab: "known" here means known to Spansh's database, not necessarily scanned by you.
    4. Either way, review the body/slot table — it pre-fills orbital/ground slot-count guesses per body (a best-effort community heuristic, not an exact formula) with a "Reset slots to guess" button per row if you've edited it and want to revert.
    5. Click Apply — populates Actual facilities in the system with a real per-body layout instead of flat aggregate slot counts. Then set your Primary station there (step 1 above) and you're ready for the Objective panel.

Note: Journal- and Spansh-sourced data for the same system merge by real body ID — scanning more of the system later and re-importing adds detail rather than starting over.

1. Force a specific port into your plan (e.g. a Dodecahedron) while keeping cost minimal

TL;DR: the Min column in Ports & Facilities numbers is a hard "build at least N of this" constraint. Combine it with minimizing Construction cost as your objective.
  1. Do the common setup above — for this one the per-body import is optional, a flat aggregate plan works fine; only the Primary station pick actually gates Solve.
  2. Open the Objective panel. Leave the mode on "Maximize a single score", and pick construction cost from the dropdown (shown all-lowercase there). The app auto-inverts direction for this one stat — picking it minimizes total commodities hauled instead of maximizing it (there's a hint under the dropdown reminding you of this).
  3. Expand Ports & Facilities numbers (folded by default). Find the Dodecahedron row. Set Min = 1. If you want exactly one and no more, also set Max = 1.
  4. Click Solve for a system.
  5. Check Solved system / Build order — you'll get exactly one Dodecahedron, with every other pick chosen to keep total commodity cost down. Don't be surprised if the plan also includes a few cheap Hubs/Settlements you never asked for: a Dodecahedron spends T3 points on an escalating curve, so the solver has to bank enough T3 first — those extra picks are the cheapest available way to earn that T3, not a mistake or a cost-minimization miss.

Notes: Min/Max here is a genuine hard constraint solved by the MILP — if your slots/points can't actually support the pick (no eligible body, not enough T3 points bankable), you'll get an infeasible result, not a silently-ignored one. There's no separate "must build" toggle anywhere else in the UI — this Min field on the Ports table is the mechanism. Also: "Construction cost" means real hauled commodities (a Dodecahedron is ~236k units) — a different number from T2/T3 points, which are a separate escalating currency you spend to afford bigger ports.

2. Cap Security at -50 (criminal/anarchy system) while nudging Wealth:Tech toward 2:1

TL;DR: Score constraints table's Security row → Max = -50 (a ceiling, not a floor — this forces security to stay deep in anarchy territory instead of merely permitting it). Objective mode → "Complex score" → pick the built-in "Wealth & tech, 2:1 ratio" preset.
  1. Do the common setup above — the per-body import isn't needed here.
  2. Open Objective → Score constraints table (below the Simple/Complex radio buttons). Find the Security row. First clear (or lower) its Min field — the app ships with a default Min = 1 on Security (a floor that keeps NPCs from interdicting your haulers once security goes negative), and a leftover Min = 1 alongside Max = -50 is a self-contradictory range that reports infeasible. Then set Max = -50.
  3. Switch the objective mode radio to "Complex score".
  4. From the Presets dropdown, choose "Wealth & tech, 2:1 ratio". Under the hood this applies 2×Wealth + Tech − |Wealth − 2×Tech| — pushes both up while pulling them toward a 2:1 relationship.
  5. Click Solve.

Caveats: Max here is a genuine hard ceiling the MILP must satisfy — the solver will actively pick security-lowering buildings (or avoid security-boosting ones) until it's at or below -50, not just "allow" a low value. "Allow criminal constructions" (further down the Objective panel) defaults to on, so Pirate Base/Criminal Outpost are already eligible builds for a scenario like this — only relevant if you'd previously switched it off. There's also no hard "exactly 2:1" constraint control in the UI — Score constraints are absolute Min/Max floors/caps only, not ratios between two stats. The preset is a soft pull, not a lock; if you need it closer to exact, solve once, check the real Wealth/Tech numbers in Solved system, then manually tighten Score constraints' Min/Max on one of the two stats and re-solve.

3. "I want Agriculture, but not Refinery or Extraction"

Prereq: do the common setup above, including the per-body import this time — Economy preferences stays greyed out without it. Not available for a from-scratch aggregate plan.

  1. Objective panel → expand Economy preferences (collapsed by default).
  2. It's a table: one row per economy (Agriculture / Extraction / HighTech / Industrial / Refinery / Tourism / Military / Terraforming / Colony), each with a "No preference" checkbox and a 0-200 slider next to it. Leaving the box unchecked means unbiased (today's default). Checking it enables the slider: 0 = Forbid (the one hard value on the scale), 1-49 is the Avoid band (a soft negative pull), 50 is neutral, 50-200 climbs through Wish → Boost → Ludicrous boost (a soft positive pull, no hard "must build this" state).
    • Agriculture row → check the box, drag the slider into Boost or Ludicrous boost (100-200) for a strong pull.
    • Refinery row → check the box, drag the slider to 0 (Forbid).
    • Extraction row → check the box, drag the slider to 0 (Forbid).
  3. Solve.

Caveats: only the slider's 0 end is a hard exclusion — it zeroes out every (building, body) combo carrying that economy. Generic ports stack multiple economies from the body they're built on (e.g. any port on an Earth-like world always carries Agriculture and High Tech and Military and Tourism together, non-selectably) — Forbidding one can rule out more building options on a body than you expect. Everywhere above 0 is a soft, continuous coefficient — it only actually biases the solve because the app's default objective expression includes the "economy preference" term (letter p); if you changed presets in tutorial 2, this stops mattering. There's no separate hard "must build this economy" state anymore — cranking a slider to 200 is still a strong pull, not a guarantee, so an unsatisfiable requirement won't make the solve report infeasible the way Forbid can. Extraction gets added to a body's economy set just from having rings or geological signals — Forbidding it can knock out otherwise-great ringed/geo bodies for other purposes too, so check which bodies the solver avoided in the results.

4. Demolish a bad early build and let the solver fix it

TL;DR: Actual facilities in the system lets you flag an already-built facility demolishable; the solver can then remove + replace it if that scores better.
  1. In Actual facilities in the system, find the body/slot with the building you regret.
  2. Tick its Demolishable checkbox (only offered for a genuinely present facility, not an empty slot).
  3. Objective → Solve. The solver can now remove that facility (refunding its points and freeing the slot) if replacing it scores better — or leave it if it's still the best option.
  4. Check Build order — a genuine remove-and-replace shows as separate Demolish and Planned rows. If the solver ends up rebuilding the exact same building type in that slot, EDCPS recognizes that as pointless churn and shows it as unchanged ("present") rather than a wasteful demolish-then-rebuild pair.

Caveats: only a narrow slice of the real mechanic is modeled — no weekly-maintenance-tick timing, no mission-loss simulation, and the primary station plus the 5 escalating-cost port types (Coriolis, Asteroid Base, Orbis/Ocellus, Dodecahedron, Planetary Port) can never be marked demolishable here. In-game, demolition refunds points/slots on the next maintenance tick — this tool models the refund as instant.

5. Chasing max Tech Level for unlocks

TL;DR: "Maximize a single score" → tech level. Add Score constraint floors on anything you don't want collapsing as a side effect.
  1. Objective → "Maximize a single score" → pick tech level from the dropdown (shown all-lowercase there — the Score constraints table below spells the same stat "Tech level").
  2. If you don't want something else tanking while you chase Tech (e.g. Security going deeply negative), add a Min floor for it in Score constraints.
  3. Solve.
  4. Check Solved system/Build order for which High-Tech-economy buildings got picked. Bodies with an ammonia world, Earth-like world, geological signals, or organics push Tech Level higher via the Colony economy override table — doing the per-body import (see Before you start) and setting High Tech to Want in Economy preferences (tutorial 3) reinforces this on top of the raw score maximization.

Caveat: "Maximize a single score" only optimizes that one stat — others aren't held constant, just not directly targeted. Always check Solved system afterward for side effects, and add Score constraints Min/Max if one is unacceptable.

6. Stacking strong links to inflate one economy on your main port

Quick mechanic refresher: a strong link forms between a port and any facility on/around the same body (40–120% contribution depending on tier). A weak link forms between a port and facilities on a different body in the system — but it's a flat 5% regardless of tier. So: to meaningfully boost one economy's share on your main port, build supporting facilities of that same economy on the same body, not scattered around the system.

  1. Decide the target economy for your primary port (Military, High Tech, Extraction, whatever).
  2. With a per-body layout imported (see Before you start), fill your primary station's other slots — space and ground, on the same body — with Settlements/Hubs of that matching economy.
  3. Check the body's own attributes against the boost/decrease table: e.g. volcanism boosts an Extraction strong link there; an icy body decreases Agriculture; a tidally-locked planet decreases Agriculture too. Pick your body accordingly if you have options.
  4. In Economy preferences, check that economy's box and drag its slider into the Boost or Ludicrous boost band (100-200) so the solver actually leans toward building matching facilities there instead of elsewhere.
  5. Solve, then hover the "i" info icon on your primary port in Solved system — the Economy ratios / Market links breakdown shows exactly how much each linked facility contributed, body by body.

Caveats: the solver's own objective term (economy_synergy) is an approximation of this — it can't solve the exact link graph inside the same optimization that's deciding the placements (that'd be circular). Always confirm the real number via the "i" info hover on Solved system, not just the objective score. If the target economy is Extraction/Industrial/Refinery, also check Actual facilities in the system's System resource level dropdown — it drives that same boost/decrease table and defaults to Pristine unless a scanned body in the system reported a real reserve level.

7. Worked example: a Civilian Planetary Outpost + orbital Coriolis for a CMM-economy body

  1. Pick (or import, see Before you start) a Rocky or Rocky Ice body. Bonus if it also has rings and/or geological signals — both add more of the metals/mining economies for free.
  2. Build a Civilian Planetary Outpost on that body's ground slot. This one is itself a port (not a supporting facility), and it's not on EDCPS's fixed-economy list, so it takes the body's own Colony economy override directly: Rocky alone → Refinery; Rocky Ice → Industrial + Refinery; add rings → also Extraction; add geological signals → also Extraction + Industrial. No separate Hub/Settlement needed — the outpost is the economy source here.
  3. Build (or plan) a Coriolis in that same body's orbital slot. Two ports on the same body strong-link to each other — the ground port's economy set passes upward to the Coriolis, so it ends up carrying the same Extraction/Industrial/Refinery mix, not just the Coriolis's own generic Colony economy.
  4. In Economy preferences (needs the per-body import from Before you start), check the boxes for Extraction / Industrial / Refinery and drag each slider into the Boost band (100+), then Solve.
  5. Verify via the Coriolis's "i" info icon in Solved system: Economy ratios should show a real strong-link contribution from the Civilian Planetary Outpost, forwarded from the ground port — distinct from a flat 5% weak link you'd get if the two were on different bodies instead.

Caveats: Colony-economy stacking is automatic and not selectable — every generic port on that body gets the same override set from the body's own attributes, so you can't opt out of Extraction on a ringed Rocky body even if you only wanted Refinery. Also, whichever of the two ports is higher-tier becomes the "dominant" one for tie-break purposes (a Coriolis outranks a Tier-1 Planetary Outpost) — that only affects EDCPS's own display tie-break, not which economies actually reach the Coriolis.

8. Cap total haul cost at 250,000t while hitting minimum Tech/Wealth/Security targets

TL;DR: four rows in the Score constraints table — Construction cost Max = 250000, Tech level Min = 100, Wealth Min = 150, Security Min = 20. All four are hard bounds, no per-body import needed.
  1. Do the common setup above — the per-body import isn't needed here.
  2. Open Objective → Score constraints table (below the Simple/Complex radio buttons).
  3. Construction cost row → Max = 250000. This caps the TOTAL commodities hauled across every new building in the plan combined, not per building — a single Dodecahedron alone is already ~236k, so a tight cap like this usually means several cheaper Ports/Hubs/Settlements instead of one huge one.
  4. Tech level row → Min = 100.
  5. Wealth row → Min = 150.
  6. Security row → Min = 20.
  7. Pick an objective for anything left over: these four bounds are all pass/fail, so the solver has no preference among multiple layouts that satisfy them unless you also give it something to actually maximize/minimize — e.g. leave "Maximize a single score" on construction cost (see tutorial 1) to squeeze the haul total down further within the 250,000t cap, or switch to "Complex score" → Default preset for a more balanced pick.
  8. Click Solve for a system.
  9. Check Solved system — Tech level, Wealth, and Security should each be at or above your requested minimum, and the total Construction cost at or below 250,000.

Caveats: all four bounds are hard constraints solved together — if they're jointly unreachable (e.g. 250,000t genuinely isn't enough commodities to reach Tech 100 + Wealth 150 + Security 20 at once), the solver reports infeasible rather than getting as close as possible; there's no soft/partial-credit mode for Score constraints Min/Max. Tech level/Wealth/Security here track the same in-game Development/Economy panel numbers you'd see in-system (net of the Dodec Update's first-station-bonus/subsequent-facility-reduction weighting this app already applies); Construction cost itself isn't a stat the game displays anywhere — it's this app's own running total of commodities hauled for the plan.

9. Let the solver plan a self-sufficient commodity/manufacturing base

Prereq: do the common setup above, including the per-body import this time — Self-sufficiency stays greyed out without it (each combo needs a real, currently-untouched body to target).

TL;DR: Objective panel → Self-sufficiency section → tick Commodity Hub and/or Manufacturing Hub, then Solve. The solver picks a suitable empty body itself and schedules the build early in the plan.
  1. Open Objective → expand Self-sufficiency (right above Score constraints; auto-expands on its own once at least one eligible body exists, so it may already be open).
  2. Two checkboxes, each with a live eligible-body count next to it:
    • Commodity Hub — a Civilian_Planetary_Outpost on an untouched High Metal Content body (with 2 Refinery Hubs) or an untouched clean Rocky body (no organics, no geological signals, not terraformable). Maximizes local production of essential colonization commodities and CMM Composite.
    • Manufacturing Hub — a Scientific_Planetary_Outpost plus 4 Refinery Hubs on an untouched High Metal Content or clean Rocky body. Maximizes refinery capacity and high-tech manufacturing.
    A checkbox is disabled (greyed out) whenever its own combo currently has zero eligible bodies in the imported system.
  3. Tick whichever combo(s) you want, then click Solve for a system.
  4. Check Build order — the forced outpost and its Refinery Hubs land right at the front of the sequence (not merely "somewhere in the plan"), and pay real construction cost/T2/T3 points like any other planned build. Nothing in Actual facilities in the system changes just from checking the box — it's a goal for the next solve, not a fact about what's already built.

Caveats: this is a player-reported heuristic, not an officially- or community-sourced rule table like most of this app's other economy modeling — and the app has no commodity-level knowledge at all, so it only knows the two ports' economy types, not whether the body will actually yield the specific commodities you need in-game. The Refinery Hub counts (2 vs. 4) are the user's own in-game "usually" observation, not a verbatim number. Body eligibility requires the body to be completely untouched (no present facility on any slot) — a body with just the primary station's slot synced onto it still counts as untouched for this purpose. Checking a box is a strong steer via a hard MILP lower bound, not a soft nudge — if the system genuinely can't afford it (not enough T2/T3 budget or ground slots), the whole solve reports infeasible rather than silently dropping the goal.
